## Decisions

- One payslip per employment per run, calculated in chunks of 20 in their own transactions; the run's status `calculating` carries a lease so the minute cron finishes an abandoned calculation.
- Each payslip stores the exact engine input and the engine fingerprint; lock stores a SHA-256 of all inputs and of all fingerprints. `payruns.verify` recomputes every payslip from its stored input with the pack versions it used.
- Locked, paid and void runs refuse every write (`run_locked`); used pay inputs and recurring items a locked run used cannot change; the kernel's `record.editing` asks payroll and refuses an Edit of a pay, job or tax record a locked payslip used.
- Void calls `lib_expenses.unmarkPaid` (claims and advances wait again and the replacement asks `payInputs` afresh), copies leave cash-in lines into pay inputs of the replacement (leave has no unmark), re-opens used inputs for it, reverses loan repayments and calls `lib_time.unlockDays`.
- A correction run recomputes what the original payslip should have been (current pay records and tax profile, the original's inputs and module items, history before the original) and stores only the differences by code against the original plus earlier corrections.
- Back pay is paid as ARREARS inputs (one per locked period, taxed by the current period's rules); the preview also shows the net effect with the packs then in force.
- Components get roles (basic, overtime, unpaid, encash, loan, advance, arrears...) so module inputs land on the right component; pack seed codes map to roles in `SEED_ROLE` (data), and the basic set copies the tags of the pack component of the same role.
- Pack codes of a payslip: the tax profile's packs, else the entity's. A code with only a draft version is a blocker (`pack_not_active`) naming the pack: India's EPF, ESI and most PT packs ship as drafts, so Indian employees run on `in` until a person activates them (the demo tests set the tax profile packs to `["in"]`).
- Warnings need an acknowledgement before approval (entity setting `warnings_need_ack`, default on); the preparer never approves their own run (approval flow default: role finance, which also reaches owners).
- Employer fields a pack read with no value become `entity_field_missing` warnings and set-up notices on Payroll home (not every undefaulted field, which would flag a 健康保険組合 rate for a 協会けんぽ employer).
- History (QA M-1): every locked payslip of the employment from 550 days back to the end of the latest tax year a pack in force reads, whatever its pay date, so a bonus dated before a locked regular run of the same period counts it (warning `paid_before_locked_run`, with the run). The engine sums a tax year in any order; `prev_regular` and `has_prev_regular` still skip a regular payslip dated after the run (engine rule), so IN and AU block a bonus dated before the month's locked regular pay instead of charging it twice. A correction keeps the history the original had.
- A lock or void sends the same people's other calculated or approved runs back to draft (note `history_changed`): their year to date changed. A pay input aimed at one run (`--payrun`) only sends that run back.
- Time inputs of a chunk are read in one `lib_time.payInputsMany` call per employment window.
- Time days lock at a run's lock only up to its input cutoff (`lockDays(..., min(window end, cutoff_day))`), never later days. Time's `adjustments` (days an earlier locked run used that changed afterwards) are paid in the next regular or final pay run, one line per day and component, named "<component> adjustment, 3 Nov 2026" with the day and reason in `explain`: overtime and premium codes at their multiplier, regular hours for hourly pay, absence days at the day rate for salaried and daily pay; late minutes change no pay. Time's issues keep their `days`, `weeks` and `month`; the screen writes them.
- Leave cashed in or paid out on leaving is valued at the leave rate: a daily or hourly rated person's own rate; salaried, annual pay over 52 weeks of the schedule's working days (SG gross rate of pay for one day, US and AU final rate of pay, UK 1/260), MY and IN the month over 26. Leave gives every cash-in in days (an hours type as hours over the person's hours a day).
- Unused leave paid on leaving (QA2 N-1) is its own earning component `LEAVE_EXIT` (role `exit_leave`), never the salary-like `LEAVE_ENCASH` (which stays for cash-ins a person asks for). Its tags are `exit_leave_payout` and `termination` plus the tags of the `LEAVE_EXIT` seed entry of each pack the entity has enabled (AU `au_unused_leave`: Schedule 7 on `AU_PAYGW_LEAVE`, not super; US federal wage tags and `us_supplemental`; GB pay tags; SG, IN, MY, JP read `exit_leave_payout` themselves and add none). `lib_payroll.syncExitComponent` writes them when components are seeded and at the start of every calculation (packs seed on boot, after migrations, and an entity's packs can change), so do not edit LEAVE_EXIT's tags by hand. The kind of each cash-in (voluntary or exit) is read from `leave_encash_requests.kind` by request id. The payslip line carries the tags into later payslips' engine history (`by_tag.exit_leave_payout`). `context.exit_leave_days` gives the packs the days paid out (IN 10(10AA)).
- Final pay and leave: leave makes the exit cash-ins (types with `payout_on_exit`, `pay_on` the last day) on `separation.approved` and `separation.changed`; the final pay run pays them through `payInputs().encash`. A leaver with a balance of such a type still left on the last day and no payout line for it gets the warning `leaver_leave_unpaid` (with the type and amount).
- `separation.changed` moves a final pay run that is not locked to the new last day (period, pay date, label, back to draft); after lock it only notes and tells payroll.
- Held pay: `payruns.get` and lists give `to_pay_minor` (net less held pay plus holds released into the run, payroll-out's reconciliation), `held_minor`, `held_count`, `released_minor`. The lock dialog shows payroll-out's `payout.run` totals (net, held, released, to the bank, cash, cheques, `balanced`); a locked run offers "Write the bank file" (`#/payroll/pay-out/<run>`). A held person's bank issues (`bank_missing`, `bank_currency_mismatch`, `bank_changed_recently`) get severity `held` and do not block; calculation blockers still do.
- Issues in plain words: payroll's own messages no longer name the person (the Issues tab groups by person); every issue keeps its code. An engine `step_error` whose formula reads an empty person, tax profile or employer value (names from the parse tree, plus `age_on` for the birth date) becomes `data_missing` with `scope`, `field`, `field_label` and a fix link; any other becomes `pack_error`; the engine text is kept in `detail`. The screen words each known code from `payroll.issue.<code>` with the structured fields (days through format.ts).
- The approval of a pay run asks for what it pays: `amount_minor` and the facts are net to pay without held pay, held pay and people held apart, released holds and the pay day; putting a hold on or taking one off after the run went for approval sends it back to calculated (approval cancelled, note `reapprove`).
- Fix where the issue is (QA2 N4): the Issues tab opens an editor for exactly the value an issue needs when the viewer may change it (a person's birth date or details with people:edit, a tax profile field, an employer field, a bank account, a starting pay record), saves and recalculates that payslip; otherwise `payruns.ask-fix` sends it to who can (HR for a person's details, the person for a missing bank account when they have a sign-in, payroll administrators for the rest) as an Inbox item, once while unread. Refusals show plain sentences from the error code and its `data.param` (never a field name); a pay change before the first day of work is `before_start` with `data.start_day`, and a joiner's pay change defaults to the first day with the reason "Starting pay" (`hire`).
- `my_pcb_year_history_missing` (my 2026.4): the Fix takes the year's earlier pay, PCB and employee EPF as an opening balance (`ytd.set` with tags `my_pcb_normal`, `my_epf_employee` and codes `MY_BASIC`, `MY_PCB`, `MY_EPF_EE`, dated the day before the period) or sets `my_pcb_no_earlier_pay` on the tax profile; that switch renders in the tax profile form from the pack's field definition.
- Opening balances (QA3 major, 2026-11-10; migration `1730004040_payroll_openings.js`, `lib_payroll_openings.js`, page `#/payroll/openings`): an entity's first pay run (no regular run locked yet), or any run while a first pay day in HR OS (`go_live_day`) is set, needs the earlier pay of every person employed before HR OS's first pay period (`startOf`: the earliest non-void regular run with a pay day on or after the go-live day, else this run) in the tax year of a pack that reads earlier pay. Without an opening balance in that tax year, or the entity's confirmation `payroll_settings.no_earlier_pay` (with `_by`, `_at`; op `ytd.no-earlier-pay`, people only), the payslip's history starts at HR OS and it gets the blocker `opening_balances_missing` (the engine's `history_short`, a step error with error code `history_short` and MY's `my_pcb_year_history_missing` fold into it); `payruns.issues` and the run's counts show ONE such blocker for the entity with `people` (per person with `--employment`). The confirmation sets the packs' "nothing paid earlier" profile fields (`NO_EARLIER_PAY_FIELDS`: `my_pcb_no_earlier_pay`) in the engine input.
- Opening balance columns come from the packs (`historyReads`): tags and codes read with `ytd`, `ytd_code`, and `ytd_since`/`ytd_code_since` read with one window (a fiscal year, a quarter; a pair of windows subtracted is about the month itself), plus the pack's statutory deductions (withheld so far) not already counted by a tag column. Labels: the pack's `tags` list, else the step name. `ytd.sheet` (people, columns, values in minor units, the confirmation), `ytd.sheet-save` (one person, merged into the opening balance of that tax year, dated the day before HR OS's first period), `ytd.import-check` / `ytd.import` (CSV: `employee` plus figure keys or labels; all rows or none). Your AI agent may check and propose, never confirm the switch. The setup guide (kernel `lib_settings.progress`, step `payroll_start`) and Payroll home (`go_live_missing`) ask for the first pay day while an entity with people has none, no confirmation and no locked regular run. The demo seed confirms the switch for its four entities before the October runs (the demo starts HR OS in October).
- Personal fields packs read (QA3): `payroll.person-set` (payroll:edit, audited, a proposal for your AI agent) sets only `birth_date`, `nationality`, `gender` (`lib_payroll_tax.PERSON_FIELDS`); a `data_missing` issue for them carries `payroll_may_set: true` and its field is the person record's (`age` is `birth_date`). The Fix opens the editor in place for payroll, in the Issues tab and in the payslip drawer of an open run (`PayslipView fix`); other personal fields go to HR with `payruns.ask-fix`.
- The sidebar lists Payroll's pay schedules only (module `nav` is empty); every payroll page, core and pay-out, is on Payroll home (`payrollPages`).
- Run names: "November 2026", "Bonus November 2026", "Final pay ... <name>"; the schedule name only when an entity has more than one.

## Contract changes and needs

- `lib_time.payInputsMany(app, ids, from, to)` per chunk; `lockDays` at lock up to the input cutoff; `unlockDays` at void.
- `lib_leave.markEncashPaid(app, ids, payrunId)` at lock (leave shipped it). After a void the replacement calls it again with the new run id; it skips requests already paid, so the request keeps the void run's id: please accept the re-mark.
- Expenses (as it shipped): `payInputs(app, employmentId, upToDay, currency, { via })` with `via: 'payroll'` in regular and final pay runs and `via: 'bank'` in reimbursement runs; items land on their `component` (claims on the category component, default `REIMB`; advances paid with the run on `ADVANCE`, both non-taxable reimbursement components seeded for every entity) and carry `ref`; recoveries from `advanceRecovery` land on the advance recovery deduction (`ADV_RECOVERY`, post stage). At lock `markPaid(app, refs, payrunId)` gets claim ids, advance ids and `{ advance, amount_minor }` for recoveries; at void `unmarkPaid(app, payrunId)`; final pay warns from `outstanding(app, employmentId)` (claims not decided, advances not paid out).
- For payroll-out: `lib_payroll_runs.markPaid(ctx, runId, { paid_at, note })`, `lib_payroll_runs.payoutItems(app, runId)`; events `payrun.locked`, `payrun.voided`, `payrun.paid`.
- For lifecycle: `separation.approved` returns `{ payrun }` (a draft final pay run); `separation.changed` moves it while it is not locked.
- Approval kind `tax_declaration` also carries tax profile self-service changes (`tax_declarations.kind = 'profile'`); no new kind was added.
- The kernel's `tax.update` lets a person write their own tax profile directly (no approval); the UI uses `taxprofile.submit`, which applies the entity's approval rule.

## Gaps

- 日額表 (non-monthly Japanese pay), India EPF/ESI/PT until their draft packs are activated, Canadian packs (not built by packs-west).
- Formula components (`calc: formula`) are stored and checked for syntax but not evaluated; use percent or fixed.
- A mid-period schedule change uses the schedule at the end of the employment window for the period's working days (pay record changes mid-period are split exactly).
- Year-end runs exist as a flag (`year_end`); the year-end documents are payroll-out's.
