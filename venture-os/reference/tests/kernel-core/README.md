# kernel-core tests

Run against a scratch copy of the app (never the delivered folder, never a live port):

1. Copy the app to a scratch folder without `pb/pb_data`; add the scratch-only test kit with `bash sync_stubs.sh` (it copies `stubs/` over the copy and runs `node tools/gen.mjs` and `node tools/gen_triggers.mjs`). The kit is a fake module `zz_test` (`cat_zz_test.js`, `lib_zz_test.js`, `events_zz_test.js`, `guide_zz_test.js`, `cron_zz_test.js`) that exercises every kernel contract, a migration with stand-ins for kernel-records' `deals`, `deal_people`, `files` and the fake module's `zz_things`, and a stand-in `lib_files.js` (`pathOf` only). None of it ships.
2. `VO_APP=<scratch copy> VO_PORT=3181 VO_BRIDGE=3281 node run_all.mjs` (each test resets the scratch database through `tools/dev/reset.sh` and starts it with `tools/dev/serve.sh <app> <port> <bridge port>`, which starts the mock bridge).

Tests: t01 empty-database read sweep (nobody, owner, partner, analyst, your AI agent) and setup; t02 sign-in, invites, lockout, PIN and recovery, members, roles, fund scope, your AI agent refused before params and PIN; t03 proposals (dry run, evidence, confidence, dedupe, supersede, accept as the accepting member, stale, expiry, promoted kinds with the op's auto check, sets) and deal scope (restricted deals, deal team, agent_allowed, fund scope); t04 triggers (the test kit's zz_review through the mock bridge: one fire with the record, a repeat ask refused while it waits, cooldowns, Retry after 24 hours, after done and after agent.cannot, the result op lands it, NDA files open only while a deal's ask waits, restricted deals, questions, the switches, the demo firm); t05 Next (aggregation, bad items reported, actions filtered by rights, snoozes, tasks) and outbound (draft, edit counts, approve and send, send key, missing attachment, the 200-with-error shape, offline, pace) and the mail helpers; t06 imports (synonyms, preview, batches, proposals) and activity (undo one change, a run as a unit, conflicts refuse the whole undo, atomic ops, a fired request stays); t07 entities and LPA validation, exchange rates (end, avg, inverse, cross, none), module settings, search, the day, comments, views, notifications, the ZIP export, cron catch-up.

Trigger economy: `e01_trigger_economy.mjs` runs against a SEEDED scratch copy (tools/dev/seed_demo.mjs): the demo firm and 24 idle hours give 0 fires, each person action fires exactly its trigger with its record, a repeat ask while it waits fires nothing, Retry fires once, each switch alone fires only its own triggers. `VO_APP=<seeded copy> VO_PORT=3181 VO_BRIDGE=3281 node e01_trigger_economy.mjs`.

Merged check: `m01_merged.mjs` runs against a scratch copy of APP with kernel-records' real collections and ops (no test kit): an empty sweep of the whole merged catalog as owner, partner, analyst and your AI agent, deals through the kernel's scope and undo, a records proposal accepted from Next, the guide and search reaching the records module. `VO_APP=<scratch copy of APP> node m01_merged.mjs`.

Speed check: `m02_next_speed.mjs` seeds a merged copy (deals, proposals, drafts, tasks), restarts it and times next.list from the Server-Timing header: the first call after a restart (under 500 ms), 30 warm calls (90th percentile under 150 ms) and 20 calls right after a change (rebuilt, under 150 ms). `VO_APP=<scratch copy of APP> node m02_next_speed.mjs`.

First requests: `m03_first_requests.mjs` restarts a seeded merged copy and times the page-load reads fired together, the same reads as one `app.batch`, and single landing reads alone (`PB_SERVE_FLAGS=--hooksPool=120` compares a bigger pool).
